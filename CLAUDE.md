# CLAUDE.md — Library Loan App

A small library web app for a **software quality class**. Users sign up, search books from Open Library, then borrow, renew, return and reserve them. The backend is a Spring Boot REST API in MVC layers using JPA and PostgreSQL.

## Ground rules for Claude (read first)

The work is broken into tasks per feature branch in `tasks.md`. Tick tasks off there as they are done.

1. **Do NOT write any tests.** No unit, integration, API, E2E or load tests, no test classes, no Postman collections, no k6 scripts. The students write all tests themselves as part of the course. Do not create anything under `src/test/`, `api-tests/`, `e2e-tests/` or `performance-tests/`. Leave those folders to the students.
2. **Keep the code simple.** This is a student assignment. Write plain, readable code a student can follow and test. No clever abstractions, no extra frameworks, no generic base classes, no event systems, no caching layers, no reactive code. When in doubt, choose the boring option.
3. **The point of the code is testable logic.** The business rules (BR-01 to BR-11 below) must be implemented exactly as written, in the service layer, so the students can test them with EP/BVA, decision tables and white-box coverage. Don't add rules that aren't listed, and don't change the values.
4. **MVC + JPA.** Controllers only map HTTP to service calls. Services hold every rule. Repositories are Spring Data JPA interfaces. Entities are JPA `@Entity` classes.
5. **PostgreSQL, no Flyway.** Do not add Flyway or Liquibase. Hibernate creates the schema from the entities (`spring.jpa.hibernate.ddl-auto=update`).
6. Keep the three testability seams below (injected `Clock`, `OpenLibraryClient` interface, rules in services). They are why the code can be tested.

## Architecture

A request goes browser → nginx → controller → service → repository.

- **Model**: JPA entities, repositories and services. Services hold the rules.
- **View**: JSON DTOs (Java records) and the static frontend that renders them.
- **Controller**: REST controllers. They hold **no business rules** (no `if` on rules), they only call services and return DTOs + status codes.

Only the service layer calls Open Library (through `OpenLibraryClient`).

## Data model (JPA entities)

Three entities. Books are **not** stored: a loan keeps the Open Library work ID (e.g. `OL45883W`) and a cached title. The library owns one copy per work, so "available" means "no active loan".

**User** (`users`)
- `id` Long, generated
- `username` String, max 20, not null, unique
- `passwordHash` String, max 100, not null
- `createdAt` LocalDateTime, not null

**Loan** (`loans`)
- `id` Long, generated
- `user` `@ManyToOne` User, not null
- `workId` String, max 20, not null
- `title` String, max 500, not null
- `borrowedOn` LocalDate, not null
- `dueOn` LocalDate, not null
- `renewCount` int, not null, default 0 (0–2)
- `returnedOn` LocalDate, nullable (null = active loan)
- `feeKr` int, not null, default 0 (0–200)
- `feePaid` boolean, not null, default false

**Reservation** (`reservations`)
- `id` Long, generated
- `user` `@ManyToOne` User, not null
- `workId` String, max 20, not null
- `createdAt` LocalDateTime, not null
- `status` enum `ReservationStatus { ACTIVE, FULFILLED, CANCELLED }`, stored with `@Enumerated(EnumType.STRING)`

Without Flyway there are no partial unique indexes, so "one active loan per book" and "one active reservation per book" are enforced **in the services** (BR-05, BR-10). That is fine and keeps the logic testable.

## Business rules

Each rule has an ID so the students' SRS, test cases and acceptance tests can point to it. Put a `// BR-xx` comment where each rule is checked. Use these exact values.

| ID | Rule | Lives in |
|---|---|---|
| BR-01 | Username is 3–20 characters (letters, digits, `_`) and unique, ignoring case | `UserService` |
| BR-02 | Password is 8–64 characters | `UserService` |
| BR-03 | A user can have at most 5 active (not returned) loans | `LoanService.borrow` |
| BR-04 | A loan lasts 14 days: `dueOn = borrowedOn + 14` | `LoanService.borrow` |
| BR-05 | A book can only be borrowed if it has no active loan. If it has an active reservation, only the reserving user can borrow it (this fulfils the reservation) | `LoanService.borrow` |
| BR-06 | A user who owes 100 kr or more cannot borrow. Owed = unpaid fees on returned loans + fees accrued so far on overdue active loans | `LoanService.borrow` |
| BR-07 | A loan can be renewed at most 2 times. Renewal is blocked if the loan is overdue or the book has an active reservation. New due date = old due date + 14 | `LoanService.renew` |
| BR-08 | Late fee: `daysLate = date − dueOn`. 0 kr if daysLate ≤ 3, otherwise 5 kr × (daysLate − 3), capped at 200 kr | `FeeCalculator` |
| BR-09 | Only the borrower can return or renew a loan. Returning stores the final fee | `LoanService.returnLoan` |
| BR-10 | A user can reserve a book only if someone else has it on loan. Max 1 active reservation per book, max 3 per user | `ReservationService` |
| BR-11 | Search text is 2–100 characters; at most 20 results are returned | `BookService` |

Fee formula (BR-08): `fee(d) = 0 if d ≤ 3, else min(5 × (d − 3), 200)`. The cap is first reached at 43 days late.

"Today = due date" counts as **not overdue** (`today.isAfter(dueOn)` means overdue).

## REST API

12 endpoints under `/api`. All except signup, login and book search require a logged-in session (else 401). Errors always return one JSON shape: `{"code": "LOAN_LIMIT_REACHED", "message": "..."}`.

| Method | Path | Body / query | Success | Main error codes |
|---|---|---|---|---|
| POST | `/api/auth/signup` | `{username, password}` | 201 | 400 invalid, 409 username taken |
| POST | `/api/auth/login` | `{username, password}` | 200 + session cookie | 401 wrong credentials |
| POST | `/api/auth/logout` | – | 204 | 401 |
| GET | `/api/auth/me` | – | 200 `{id, username, owedKr}` | 401 |
| GET | `/api/books` | `?q=tolkien` | 200 list (max 20) | 400 q too short/long, 502 Open Library down |
| GET | `/api/books/{workId}` | – | 200 with `available`, `reserved` | 404 |
| GET | `/api/loans` | – | 200 my loans with due date + fee so far | 401 |
| POST | `/api/loans` | `{workId}` | 201 | 409 limit / not available / reserved, 402 debt ≥ 100 kr |
| POST | `/api/loans/{id}/renew` | – | 200 new due date | 409 max renewals / overdue / reserved, 403 not yours |
| POST | `/api/loans/{id}/return` | – | 200 with final fee | 403 not yours, 409 already returned |
| POST | `/api/reservations` | `{workId}` | 201 | 409 not on loan / already reserved / you hold max 3 |
| DELETE | `/api/reservations/{id}` | – | 204 | 403 not yours, 404 |

## Key classes

| Class | Layer | Responsibility |
|---|---|---|
| `AuthController`, `BookController`, `LoanController`, `ReservationController` | C | Map HTTP to service calls, return DTOs and status codes. No business rules |
| `UserService` | M | BR-01, BR-02, signup, login (BCrypt check) |
| `LoanService` | M | `borrow` (BR-03–06), `renew` (BR-07), `returnLoan` (BR-09) |
| `FeeCalculator` | M | BR-08, a pure function `int feeFor(LocalDate due, LocalDate date)` |
| `ReservationService` | M | BR-10 |
| `BookService` | M | BR-11, merges search results with `available` / `reserved` flags |
| `OpenLibraryClient` (interface) + `HttpOpenLibraryClient` | M (gateway) | Calls `{OPENLIBRARY_BASE_URL}/search.json?q=...&limit=20` |
| `UserRepository`, `LoanRepository`, `ReservationRepository` | M | Spring Data JPA derived queries, e.g. `countByUserIdAndReturnedOnIsNull` |
| `GlobalExceptionHandler` (`@RestControllerAdvice`) | C | Maps domain exceptions to status + `{code, message}` |
| `ClockConfig` | config | `@Bean Clock clock()` returns the system clock |

### Design for testability (keep these)

- **Time comes from an injected `Clock`.** Always `LocalDate.now(clock)`, never `LocalDate.now()`. Students will inject `Clock.fixed(...)`.
- **Open Library sits behind the `OpenLibraryClient` interface**, so it can be mocked. Base URL comes from the `OPENLIBRARY_BASE_URL` property.
- **Rules live in services**, injected via constructor injection (no field `@Autowired`).
- **Domain exceptions** are plain unchecked classes in `exception/`. Each carries the code string the API returns (e.g. `LOAN_OVERDUE`), so tests can assert on the code, not the message.

### Reference: `LoanService.renew`

Five checks in a fixed order (a clear control-flow graph for white-box testing). Implement it like this:

```java
public Loan renew(long loanId, long userId) {
    Loan loan = loans.findById(loanId).orElseThrow(NotFoundException::new);
    if (loan.getUser().getId() != userId)    throw new NotYourLoanException();      // BR-09 → 403
    if (loan.getReturnedOn() != null)        throw new AlreadyReturnedException();  // → 409
    LocalDate today = LocalDate.now(clock);
    if (today.isAfter(loan.getDueOn()))      throw new LoanOverdueException();      // BR-07 → 409
    if (loan.getRenewCount() >= 2)           throw new MaxRenewalsException();      // BR-07 → 409
    if (reservations.existsByWorkIdAndStatus(loan.getWorkId(), ReservationStatus.ACTIVE))
                                             throw new BookReservedException();     // BR-07 → 409
    loan.setDueOn(loan.getDueOn().plusDays(14));
    loan.setRenewCount(loan.getRenewCount() + 1);
    return loans.save(loan);
}
```

## Docker Compose

`docker compose up --build` starts `db`, `backend` and `frontend`. The app is at http://localhost:8080; the API directly at http://localhost:8081.

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_DB: library
      POSTGRES_USER: library
      POSTGRES_PASSWORD: library        # local dev only
    ports: ["5433:5432"]                # 5433 on the host
    volumes: [dbdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U library"]
      interval: 5s
      retries: 10

  backend:
    build: ./backend
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/library
      SPRING_DATASOURCE_USERNAME: library
      SPRING_DATASOURCE_PASSWORD: library
      OPENLIBRARY_BASE_URL: https://openlibrary.org
    depends_on:
      db: { condition: service_healthy }
    ports: ["8081:8080"]

  frontend:
    build: ./frontend
    depends_on: [backend]
    ports: ["8080:80"]                  # nginx: static pages + /api proxy

volumes:
  dbdata:
```
